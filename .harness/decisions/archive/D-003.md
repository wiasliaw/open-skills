# D-003: codewalk is interactive only; the landed walkthrough is a reading record with an honest commit pin

- **Status**: active
- **Date**: 2026-09-29
- **Decision**: `codewalk` runs only when a reader can reply turn by turn; in a subagent or headless run it does not walk or land and answers directly or says the walk needs an interactive session. It is no longer dispatchable by harness-flow. The landed file is a reading record of the walk, not a project deliverable, so the session running the walk writes it directly even in a harness-adopted project. Each stop is a single stop record (number, title, `file:line`, literal exactly-once content anchor, verbatim snapshot, SMIG narrative) captured and verified when its code is read; the orientation stop is stop 1 and stop counts cover orientation plus core-path stops (map and closing are framing). The commit pin is `git rev-parse HEAD` plus a coverage check at landing: modified, untracked, ignored, or out-of-repo citations are listed as `<sha> + uncommitted changes in <files>`, snapshots are re-checked verbatim before pinning, and a failed `rev-parse` records `unknown`. PR walkthrough and refresh modes remain deferred.
- **Rationale**: A one-stop-per-turn walk cannot reach landing without a reader, and harness-flow forbids its main session from producing deliverables while its implementor has no reader — supporting orchestrated runs needed an unattended mode that contradicted the skill's core loop, for little value. A pin that ignores dirty, ignored, or out-of-repo files, or snapshots captured before the tree moved, silently misstates what was read; content anchors plus an honest pin keep the file checkable without promising it stays correct.
- **Rejected alternatives**: Unattended mode for orchestrator dispatch — splits the core loop into two behaviors and still leaves the deliverable-ownership conflict with harness-flow. Landing dispatched to the implementor as a deliverable — adds orchestration for a reading aid. Capturing each record only in the turn that presents it — failures after the map and numbering are shown would invalidate them. Pinning with plain `git status --porcelain` — silent for gitignored files and fails on out-of-repo paths.
