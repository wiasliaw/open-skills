# D-002: codewalk v1 is a standalone anchored walkthrough; PR and refresh modes deferred

- **Status**: superseded by D-003
- **Date**: 2026-09-29
- **Decision**: `codewalk` ships as a standalone skill (like request-code-review), independent of `.harness/` and dispatchable by harness-flow as an ordinary skill, with two modes only — codebase tour and topic trace. The conversation is the tour; the landed markdown file is its verifiable record, pinned to the generation-time commit SHA with a content anchor and verbatim snapshot per stop. Stop counts cover the orientation and core-path stops; the map and closing are framing, not stops.
- **Rationale**: Content anchors plus a commit pin and snapshot make a walkthrough checkable against later code without promising it stays correct, which keeps a future refresh mode possible without committing to it now. Treating map and closing as framing lets "every stop passes SMIG and carries an anchor and snapshot" hold without exception.
- **Rejected alternatives**: PR walkthrough mode in v1 — its trigger surface overlaps request-code-review/receive-code-review and needs boundary work first. Refresh/re-verify mode in v1 — deferred until the landed format has been used. Line-number-only anchors — drift silently after any edit. Counting map and closing as stops — made the SMIG and anchor rules self-contradictory (review round 1 failure).
- **Supersedes**: none
