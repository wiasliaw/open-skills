# D-008: the sentinel is read-only and the orchestrator alone writes the loop journal

- **Status**: superseded by D-011
- **Date**: 2026-11-10
- **Decision**: The use-loop sentinel writes no file inside the project, runs no version-control command, calls no mutating tool, spawns no agent, and asks the user nothing. Its only output is the final handoff message. The orchestrator writes `.project/loops/<id>.md` and appends each handoff verbatim. The agent definition carries no `tools:` allowlist; the read-only property is enforced by its prohibitions.
- **Rationale**: An unattended agent that can wait for hours must not be able to mutate the project or external systems on a stale or misread condition. Keeping the journal with the orchestrator matches the existing boundary in ARCHITECTURE: agents never write `.harness/` or work-unit state. A `tools:` allowlist was not used because `tool` checks must reach arbitrary read-only MCP tools, such as Linear, which cannot be enumerated in advance.
- **Rejected alternatives**: the sentinel appends its own handoff to the journal — would give an unattended agent a write path into the project and break the agents-never-write-state boundary. A `tools:` allowlist of Bash, Read, Grep, Glob — would block the MCP tools that `tool` checks need.
- **Supersedes**: none
