# D-005: Realize the graph with three generic actors, contractual permissions, and a single work-unit.json

- **Status**: superseded by D-006
- **Date**: 2026-09-30
- **Decision**: The WOR-33 graph is realized inside open-skills (not a new plugin) with exactly three fixed roles — orchestrator skill, generic implementor agent, generic reviewer agent. Node identity is data in the dispatch payload, built per stage from the `graph-node-*` specs, including per-stage skill assignments for both actors. Permissions are contractual (written into dispatch prompts). Graph execution state is a single `work-unit.json`, written only by the orchestrator; no parallel markdown state.
- **Rationale**: Generic actors maximize reuse of general skills and keep the agent surface at two definitions regardless of node count; the node specs written in change `graph-engineering-node-specs` double as the dispatch source, so specs stay the single source of node behavior. A single JSON state makes conditional-edge inputs (fail counters, fast-path flag, ticket statuses) machine-readable without drift.
- **Rejected alternatives**: per-node agent definitions with mechanical tool whitelists — stronger enforcement but N agent files that duplicate the node specs and dilute skill reuse; JSON + markdown twin state — human-readable but two sources of truth that drift; a separate graph plugin — would rebuild the memory layer and compete with harness-flow for the orchestrator seat.
- **Supersedes**: none
