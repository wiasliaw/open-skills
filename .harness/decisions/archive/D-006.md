# D-006: Four fixed actors — a generic Advisor tier sits before Human Escalation

- **Status**: superseded by D-007
- **Date**: 2026-09-30
- **Decision**: The graph is realized with four fixed roles: orchestrator skill, generic implementor, generic reviewer, and a generic Advisor — a read-only LLM analysis agent consulted when a stage is blocked or fails twice. The Advisor issues retry guidance at most twice per problem; if both advised retries fail, the orchestrator stops and hands the problem to Human Escalation. Unblocking (advisor advice and human unblock alike) resumes at the node recorded in `work-unit.json.blocked_at`. All other elements of the realization stand unchanged from the prior decision: node-as-data spec-driven dispatch, contractual (prompt-carried) permissions, and a single orchestrator-written `work-unit.json`.
- **Rationale**: Human intervention should be the last resort, not the first escalation; an LLM advisor absorbs the cheap share of unblocking (mirrors the project owner's own working principle of consulting an advisor when the same error recurs). Recording `blocked_at` generalizes the resume edge and closes the previously flagged gap where non-Build stages had no return path from escalation.
- **Rejected alternatives**: three actors with direct-to-human escalation (D-004 amends this) — humans absorb every second failure, expensive and slow; Build-only resume with cancel-elsewhere — discards invested work in non-Build stages; per-stage advisor definitions — same duplication argument that rejected per-node agents.
- **Supersedes**: D-005
