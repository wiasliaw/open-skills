# D-008: Frequently misexecuted mechanics become zero-dependency Node scripts; prose keeps policy

- **Status**: active
- **Date**: 2026-10-01
- **Decision**: Agent behaviors that are frequently misexecuted with destructive or silent consequences are moved from skill-page prose into executable scripts; everything else stays prose. Scripts are zero-third-party-dependency Node.js (>= 20, directly runnable `.mjs`/`.cjs`, no package.json/node_modules/build step), live under the owning skill's `scripts/` directory, and are never merged into a shared package. The split is mechanics vs. policy: the script owns the dangerous mechanics (worktree creation with hooks disabled, stale-registration recovery, reuse checks, config validation), the skill page owns policy (naming, cadence, cleanup ownership, handoff records) and calls the script. First application: `skills/use-worktree/scripts/worktree.mjs` with `ensure --branch` (Build), `ensure --detach` (codewalk), and `setup` subcommands, specified in the `use-worktree-skill` OpenSpec change; this supersedes that change's earlier "self-contained page, plain git commands, no supporting scripts" premise (previously verified as F-015/F-016).
- **Rationale**: Spec prose describing exact procedures (stale-registration recovery, hooks/LFS flags, info/exclude newline handling) is the failure surface: agents improvise under error conditions — the destructive case being `git worktree prune` or `--force` removal of a directory holding uncommitted work — and loud CLI failures self-correct cheaply, so only destructive/silent misexecution justifies a script. The screening criterion (owner, 2026-10-01) rejected scripting review-fetching (loud failures, command lists suffice) and scope resolution (cheap, visible errors). Zero dependencies keep the plugin installable with no package manager; per-skill placement keeps standalone skills standalone.
- **Rejected alternatives**: pure prose (status quo) — the misexecution it allows is the problem being solved; bash — JSON validation and cross-platform path handling are error-prone without a real runtime; one bundled package/CLI for all scripts — couples standalone skills and adds a build/install step; third-party dependencies — require package management the repo deliberately lacks.
- **Supersedes**: none
