# D-007: the sentinel waits only inside foreground Bash calls

- **Status**: active
- **Date**: 2026-11-10
- **Decision**: The use-loop sentinel subagent waits for a state change only inside foreground Bash calls, each with an explicit timeout of at most 9 minutes, re-armed until the change or the deadline. It never uses `run_in_background`, the `Monitor` tool, or `ScheduleWakeup` to wait.
- **Rationale**: Two probes on 2026-11-10 (Claude Code 2.1.321). A general-purpose subagent that started an `until` loop with `run_in_background: true` and ended its turn was not rewoken within 4 minutes after the shell detected the event. The same loop in a foreground Bash call cost zero model turns while waiting and the orchestrator received the completion notification within 1 second. Foreground waits are the only primitive with verified wake-up behavior, and the 600000 ms foreground cap forces the re-arm rule.
- **Rejected alternatives**: background Bash inside the subagent — not reliably rewoken (probe 1). `Monitor` inside a subagent — behavior unverified, and a monitor stops when the session is backgrounded. `CronCreate` or `ScheduleWakeup` — fire into the orchestrator session, which defeats the context-isolation goal.
- **Supersedes**: none
