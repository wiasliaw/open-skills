# D-007: Work-unit state is a folder — routing state in state.json, events in log.ndjson, artifacts in per-stage directories

- **Status**: active
- **Date**: 2026-10-01
- **Decision**: A work unit's execution state is a folder `<work-units-location>/<id>/`: `state.json` holds only machine-routing fields and folder-relative file pointers (orchestrator sole writer, bounded size); `log.ndjson` is the append-only event stream (orchestrator sole writer, one JSON object per line); each executed node gets a `<stage>/` directory where the producing actor writes its own artifacts (implementor outputs, reviewer reports, advisor advice; human gate decisions recorded by the orchestrator). Trigger creates the folder; archive moves it whole. All other elements of the realization stand from the prior decision: four fixed actors with an Advisor tier (≤ 2 consults, then human, resume at blocked_at), node-as-data spec-driven dispatch, and contractual prompt-carried permissions.
- **Rationale**: A single JSON bloats with every stage — the log grows unboundedly, every append rewrites the whole document, and large stage content would transit conversation context to reach the orchestrator. Stage-keyed directories align storage with dispatch granularity (a dispatch names its stage directory; skipped stages leave no trace) and let producers write large artifacts directly while the routing surface stays small and single-writer.
- **Rejected alternatives**: single `work-unit.json` carrying everything (the bloat and rewrite-per-append problem; superseded element of D-006); artifact-type top-level dirs (reviews/, advice/) instead of stage-keyed — weaker alignment with dispatch and skip semantics; log kept inside state.json — append rewrites the whole file and mixes immutable history with mutable state.
- **Supersedes**: D-006
