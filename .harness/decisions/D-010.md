# D-010: the use-loop journal location is a default with a stated override rule, resolved once per loop

- **Status**: active
- **Date**: 2026-11-10
- **Decision**: The journal lives by default at `.project/loops/<id>.md` under the project root. When an instruction in effect for the session maps plugin state or `.project/` to another root, the orchestrator resolves the location per that instruction at loop creation, tells the user the resolved path before the first write, and uses that one location for the loop's whole life including archive. The sentinel dispatch carries nothing about the location.
- **Rationale**: In the 2026-11-10 acceptance probe the orchestrator wrote the journal under `~/.local/state/claude/<slug>/` because the user's global CLAUDE.md maps plugin state there. A skill that hardcodes one path contradicts such instructions; a skill that leaves the choice open risks a loop whose rounds land in different places after compaction. The project owner asked for a default plus situational judgment. Fixing the resolution to loop creation, and announcing it, keeps the journal findable for the loop's whole life.
- **Rejected alternatives**: one fixed path — conflicts with user or project plugin-state rules. Free per-round judgment — the orchestrator can lose the journal across compaction. A location field in the sentinel dispatch — the sentinel never touches the journal (D-008), so the field would only widen its surface.
- **Supersedes**: none
