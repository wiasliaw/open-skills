# D-003: init detects the adoption state first and classifies project/external × first init/re-init

- **Status**: active
- **Date**: 2026-09-29
- **Decision**: init's first step, read-only and before any interview, gathers evidence — the canonical project root `P` (`git rev-parse --show-toplevel`, else `pwd -P`); a root `CLAUDE.md` counts only if it carries the adoption marker (harness-flow or legacy agent-flow load directive, a `## Harness` section, or the legacy `## Short-Term Work-Unit Tool` section); a root `.harness/`; the root `CLAUDE.local.md` (tracked?, shim import?, target present?, target `project root:` = `P`?); and the `project root:` bullet of each `~/.open-skills/*/HARNESS.md`. It classifies by the first matching rule: anomalies (both declarations, several external matches, dangling shim, root mismatch, tracked `CLAUDE.local.md` with private) stop and ask; then project re-init; then external re-init (re-attaching a lost shim); else first init, where the storage-mode question decides project vs external first init.
- **Rationale**: Review of the private-mode change found that treating any root `CLAUDE.md` as an adoption made private mode unreachable in repos with their own CLAUDE.md and rewrote upstream files, and that finding a private harness only through the shim let a lost shim trigger a fresh interview that overwrote an unversioned harness. Deciding the case before asking anything, and stopping on ambiguity, removes both. Existing private harnesses are found by their `project root:` back-pointer — the listing mechanism D-002 already names — so the slug stays a naming rule and never becomes a lookup key.
- **Rejected alternatives**: Slug lookup to find an existing private harness — lossy and breaks if the slug rule or the directory suffix differs; D-002 rejected it. Detecting a private harness at the fill step — too late, the interview has already run as a first init. Treating any root `CLAUDE.md` as shared adoption — misroutes the private mode's own audience. Silently picking one declaration when both exist — no safe default; the user decides.
- **Supersedes**: none
