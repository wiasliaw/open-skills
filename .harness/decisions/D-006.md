# D-006: pm ships public policy defaults only — workspace and project values live in the Linear project charter

- **Status**: active
- **Date**: 2026-10-30
- **Decision**: `skills/pm/policy.md` holds only public, generic defaults: status mapping, WIP limit, lease length, who may open, move, push, and merge cards, branch naming, label names, section heading names, and Tidy thresholds. Any value that differs for a workspace or a project, including localized section headings, lives in the project charter in Linear and overrides `policy.md`. The skill names no workspace, team, project, or person.
- **Rationale**: The plugin is published through a public marketplace. A policy file holding one owner's workspace rules would publish internal names and impose that owner's rules on every installer. The project charter already exists per project (`references/project.md`) and is read before the first action, so it is the one override layer.
- **Rejected alternatives**: Ship the owner's workspace policy as `policy.md` — publishes internal context and binds every installer to one workspace. Add a separate workspace-level policy document in Linear — a second lookup layer with no v1 need, since every pulled card belongs to a project and its charter.
- **Supersedes**: none
