# D-005: use-worktree is config-free on main — no config file, no setup subcommand, fixed HEAD base and .project/worktrees location

- **Status**: active
- **Date**: 2026-10-16
- **Decision**: On main, `scripts/worktree.mjs` reads no config file and has no `setup` subcommand. A new `wu/<id>` branch starts at the main checkout's `HEAD`, worktrees live at `.project/worktrees/<id>`, and the remote for an existing non-`wu` branch is `origin`. The `config`, `setup_failed`, and `base_ref_missing` error codes are removed, and the remaining exit codes keep their numbers. Preparing a new worktree (installing dependencies and similar) follows the consuming project's own instructions and is outside the skill. The skill is still a standalone skill ported by file-level copy and is not wired into harness-flow. Evals are not ported, and `milestone/graph-engineering` is left as-is with no back-sync. The script now differs from the milestone copy.
- **Rationale**: The project owner set the direction: main ships a plugin that needs no configuration. The milestone's `.harness/config.json` contract (base ref, remote, location, `worktree_setup`) came from graph engineering, where `init` generated that file. On main nothing generates it, so it would be a hidden, hand-written input. Without it, `setup` has no input. The zero-config behavior the script already had (`HEAD` base, `.project/worktrees`) becomes the only behavior. Keeping the exit-code numbers stable avoids silently changing the meaning of codes that consumers branch on.
- **Rejected alternatives**: Keep the optional `.harness/config.json` (D-004) — the main plugin needs no config, and a user-authored file under `.harness/` conflicts with the orchestrator-only write rule. Keep the script byte-identical and only stop documenting config — a hidden behavior a stray file could trigger. Keep `setup` as a permanent no-op — dead surface. Base on the remote default branch with a `.worktrees/` location — rejected by the project owner in favor of the existing `HEAD` + `.project/worktrees/` defaults.
- **Supersedes**: D-004
