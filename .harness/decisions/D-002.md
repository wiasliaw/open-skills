# D-002: Private harness mode stores the whole harness tree in ~/.open-skills/<slug>/, reached by a CLAUDE.local.md import shim

- **Status**: active
- **Date**: 2026-09-29
- **Decision**: Besides the shared (in-repo, git-tracked) mode, init offers a private mode that keeps the whole harness tree — `HARNESS.md` (the harness declaration: the same filled CLAUDE.md template plus a `project root:` back-pointer, with absolute paths), `.harness/`, and `.project/` — under `~/.open-skills/<slug>/`, where the slug is the repo's absolute path with non-alphanumeric characters replaced by `-`. That directory is not git-managed. The repo holds only a gitignored-by-`.git/info/exclude` `CLAUDE.local.md` shim whose bare `@` import names the absolute `HARNESS.md` path; the shim's path is the authoritative repo → harness pointer and the slug is used only once, at init, to name the directory. There is no central registry; collisions get a numeric suffix.
- **Rationale**: A contributor to a repo maintained by others needs a harness that leaves no trace in the repo. Keeping the internal layout identical to shared mode keeps harness-flow/handoff logic nearly mode-agnostic (they resolve a harness declaration and a harness root). Separating the declaration from the per-agent shim lets a future agent (e.g. codex) get its own shim pointing at the same HARNESS.md. `.git/info/exclude` keeps the working tree clean without editing the other maintainers' `.gitignore`.
- **Rejected alternatives**: Central registry mapping repos to harness directories — a second, drift-prone source of truth for a single lookup need. Slug as lookup key — lossy (`my-repo` vs `my/repo`) and breaks when the repo moves. Git-managing `~/.open-skills/` — not requested; adds a repo to maintain. A trimmed HARNESS.md holding only the load directive, Workflow table, and Harness bullets — would split the CLAUDE.md shape into two contracts for the consumers.
- **Supersedes**: none
