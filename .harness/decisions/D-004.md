# D-004: Adopt OpenSpec as the declared work-unit tool

- **Status**: active
- **Date**: 2026-09-30
- **Decision**: OpenSpec (CLI 1.6.0, spec-driven schema) is the project's declared work-unit tool. Work-unit contract sections may point to an OpenSpec change under `openspec/changes/<change-id>/` (proposal = scope, delta specs = verification targets); harness loop state (Features table, Review Log, Notes) stays in the work-unit state file. Design specs — starting with the WOR-33 graph-engineering execution graph — are captured as OpenSpec changes rather than ad-hoc docs.
- **Rationale**: WOR-33 requires per-node specs with a validatable structure; OpenSpec provides an enforced schema (`openspec validate --strict`) and a proposal→apply→archive lifecycle, giving reviewer-executable verification for spec work that plain markdown docs lack. The harness-flow template already supports a declared work-unit tool via pointers, so no loop change was needed.
- **Rejected alternatives**: `docs/graph-engineering/` per-node markdown pages — no schema validation, and would blur C-002's user-facing-docs boundary; a new top-level `specs/` directory — same validation gap plus a bespoke convention to maintain; single large design doc — unreviewable granularity for 12 node specs.
- **Supersedes**: none
